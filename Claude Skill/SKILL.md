# Blind Resume Evaluation

A protocol for using AI to judge resumes without being misled by the model doing the judging. Derived from a controlled experiment (Claude vs ChatGPT vs Gemini) in which every model, shown three resumes blind, picked its own. See the parent repository for the full method, transcripts, and evidence.

## When to Use This Skill

Use this skill when the user:
- Asks which of several resume versions they should send
- Wants an AI to review, critique, or score a resume
- Is choosing between variants generated by different AI tools
- Mentions: "which resume is better", "review my resume", "which version should I use", "rate my resume", "did the AI pick a good one"

Use this skill *before* acting on any single model's verdict about a resume. A lone model's opinion of a resume is not trustworthy on its own, and this skill explains why and what to do instead.

## The Core Finding

When three leading models were each shown the same three resumes and asked which to pick, without being told which one they had written, **every model picked its own.** Self-preference bias is real, consistent, and invisible to the model exhibiting it.

The bias does not make the analysis worthless. Each model still produced sharp, specific critiques of the others. It does mean that a single model's *verdict* ("this is the best one") is the least reliable thing it says. The value is in the reasoning, and above all in where independent models agree.

## The Protocol

### Step 1: Generate variants with an identical prompt sequence
If producing the variants, give every model the same controlled sequence from the same source material, so differences in output are the model's choices and not different inputs. The reference sequence: spot the flaws, rewrite for impact, ATS boost, craft the hook, upgrade experience, format fix.

### Step 2: Strip authorship before any evaluation
Never tell a model which version it wrote. Present the candidates as anonymous "Resume 1 / Resume 2 / Resume 3." Authorship cues trigger self-preference. Hiding them is the single most important step.

### Step 3: Evaluate across more than one model
Ask each model the same question, for example: "Of these resumes, which would you choose for a [role] and why?" One model is an opinion. Two or more, compared, is data.

### Step 4: Treat convergence as the primary signal, but verify it
Where independent models agree without coordinating, weight it heavily. In the source experiment, two models independently recommended nearly the same hybrid resume, unprompted. That agreement was worth more than any single verdict.

Convergence is a strong signal, not proof. In the same experiment, two models independently flagged a posting count ("8,800+") as an inflated round number, and both were wrong: the figure was a real combined total, documented in a public repo the reviewers could not see. **Convergence tells you where to look, not always what the answer is.** Verify any flagged fact against ground truth before acting.

### Step 5: Ask for the hybrid, not the winner
The useful output is rarely "pick this one." It is "take this opening from A, this experience structure from B, this curation logic from C." Explicitly ask each model to assemble the best version rather than crown a winner.

### Step 6: Check the opening line first
Across all three models, the professional summary or first sentence was treated as the deciding signal, doing most of the work before a recruiter reads further. Optimise it first. Lead with evidence of something built or delivered rather than a job-title label.

### Step 7: Supply receipts, or expect false flags
A reviewer without access to your underlying data will flag your strongest, most complete claims as unverifiable, precisely because it cannot see behind them. When possible, give the reviewing model the supporting context (datasets, links, breakdowns). Context you leave out of the document becomes a liability even when you are right.

## Rules of Thumb (the findings, condensed)

- **Self-preference bias is always present.** Hide authorship; never trust one model's pick.
- **Convergence is the signal.** Independent agreement outweighs any single verdict, but is not infallible.
- **The opening sentence carries the resume.** Fix it first, lead with proof.
- **Precision beats vagueness, but omitted context reads as a red flag.** A specific number needs its receipts attached, or a reviewer will tell you to cut your best real figure.
- **Skills placement is a statement of priorities.** Front-loaded versus buried is read as a choice about what matters.

## Output

Deliver:
1. A recommended resume, ideally a hybrid, with each borrowed element attributed to which source variant it came from and why.
2. A short per-model summary of what each reviewer prioritised (its evaluation framework), so the user sees the criteria, not just the verdict.
3. A list of any facts or figures the models flagged, marked "verify before use," with a note on whether each is genuinely weak or just missing its supporting context.
